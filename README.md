# 随手记（AutoLedger）

一个完全离线的安卓记账 App：**不用手动记账**，微信 / 支付宝付款后自动把这一笔记进本地账本，自动归到两级消费分类，月底按类别下钻出月度账单，年末还能看一整年的收支全貌。手动记账同样是一等功能，现金、代付、漏记都能补；分类也能按自己的习惯改名、换图标、增删。

> 数据全部保存在手机本机（SQLite），应用**没有申请网络权限**，不存在任何上传行为。

---

## 功能一览

| 模块 | 能做什么 |
|---|---|
| 记一笔 | 底部自绘数字键盘，支出 / 收入一键切换；金额、分类、账户、时间、对方、备注在同一页填完 |
| 两级分类 | 一级类（饮食 / 出行 / 日用 / 购物 / 学校 / 居住 / 医疗 / 通讯 / 爱好 / 其他）下挂二级类（如「饮食 → 零食 / 饮料 / 水果 / 聚餐」），可自建分类 |
| 分类管理 | 一级类 / 二级类都能**改名、换图标、换颜色、挪到别的一级类、删除**；改坏了随时「恢复内置」 |
| 消费记录 | 按天分组的明细流水，一眼看到当天花了多少、账户走了哪条渠道 |
| 月度账单 | 支出构成环形图、按一级类的排名与占比，**点一级类进「分类下钻」页看二级类构成与该类逐笔明细** |
| 年度账单 | 全年收支 + 12 个月走势 + 年度分类分布（同样能下钻）+ 花得最多的月份 / 最大单笔 / 花钱最多的对象 |
| 自动记账 | 支付通知、支付成功页（无障碍）、账单 CSV 导入三条来源，自动去重 |
| 后台常驻 | 一个开关：在通知栏常驻一条入口，从最近任务划掉 App 也能继续自动记账 |
| 链路自检 | 「我的」顶部会诚实显示监听是否真的活着，断了给一个「重新连接」按钮，不用重启手机 |
| 我的 | 通知使用权、辅助记账、省电策略放行、分类管理、分类规则、采集日志、导入导出、清空数据 |

## 一、安装

1. 把 `app-release.apk` 传到手机（微信文件传输 / 数据线 / 网盘均可）。
2. 点击安装。首次会提示「来自未知来源」，在系统设置里允许本次安装即可。
3. 最低支持 Android 8.0（API 26）。

## 二、让它开始自动记账（关键一步）

自动记账靠读取**支付通知**实现，需要你手动授予一次「通知使用权」，安卓系统不允许静默获取：

1. 打开 App → 底部「我的」→ 点顶部卡片上的 **去开启通知使用权**（或「通知使用权设置」）。
2. 在系统页面里找到「随手记」，把开关打开。
3. 回到 App，「我的」页顶部会显示 **记账运行中**。

同时请确认：

- 手机系统里 **微信 / 支付宝的通知是打开的**（有些用户关了通知，就收不到）；
- 微信里「微信支付」服务通知不要设为免打扰。

授权后，付款时会自动记账，并弹一条轻提示，例如：

```
已自动记账 · 餐饮
-25.00  星巴克  · 待分类
```

### 记账来源

| 来源 | 说明 | 需要什么 |
|---|---|---|
| 微信支付通知 | 微信付款后自动记账 | 通知使用权 |
| 支付宝支付通知 | 支付宝付款后自动记账 | 通知使用权 |
| **支付成功页（可选）** | 付款没弹通知时，直接读微信 / 支付宝的「支付成功」页补记 | 无障碍授权，默认关闭 |
| **账单导入** | 微信 / 支付宝的历史账单 CSV 一次性补进账本 | 手选一个文件 |
| **手动记账** | 现金、代付、漏记的，点右下角「+」自己记；自动记下的也能随时编辑 / 删除 / 改分类 | 无 |

> 同一笔钱如果同时被「支付通知」和「支付成功页」抓到，App 会自动去重，只记一条。
>
> 判重是分档做的，不会把「连着付了好几笔同样金额」误当成一笔：
> 同一条通知在 20 秒内被系统反复投递才算重复，不同来源（通知 / 账单）之间给了 4 分钟窗口。
> 支付成功页这条链路不抢记：它比通知晚 8 秒出场，先确认最近没有同额记录才落库。
>
> 支付宝「**碰一下**」的支付成功页上，金额是动画画上去的：窗口刚出现那一帧页面上还没有金额。
> 这条链路会在 0.35 / 0.9 / 1.8 秒各回看一次，等金额渲染出来再记，所以碰一下同样不会漏。
>
> **余额宝 / 零钱通的收益播报**（每天凌晨发放）不会被记成收入 —— 它带金额、也写着「到账」，
> 但既不是消费也不是真实进账，更没有交易对方。这类通知会在采集日志里留一条「跳过」并写明原因。

### 让它更稳：通知监听会「静默掉线」

安卓有个长年未修的缺陷：通知监听所在进程被系统回收后，系统**不会重新绑定**它，
但「通知使用权」在设置里依然显示已开启。表现就是——刚装好能记一笔，之后就没反应了，
以前只能靠重启手机或者手动把权限关掉再打开。

App 现在自己处理这件事：

- 回到前台、开机、App 升级、后台常驻心跳都会做一次活性自检；
- 判定依据是「最近一次收到任意通知的时间」，而不是权限开关——后者会说谎；
- 可疑时请求系统重新绑定，确认断了才动用「组件重置」强制重连；
- 「我的」顶部会直接告诉你链路状态，异常时给一个 **重新连接** 按钮，点一下就好。

另外两件事对稳定性影响同样大，建议一并做掉：

| 项目 | 在哪 | 为什么 |
|---|---|---|
| 省电策略放行 | 我的 → 省电策略放行 | 国产 ROM 的省电策略是「通知监听被杀」的头号原因 |
| 后台常驻运行 | 我的 → 后台常驻运行 | 通知栏常驻一条入口，从最近任务划掉 App 也不断链（`stopWithTask=false`） |

后台常驻默认是**关**的，只有你自己打开才会启动（前台服务会在通知栏留一条常驻通知，这是安卓的硬性要求）。
开机、App 升级后它会自动把服务重新拉起来，不需要你手动开一次。

### 某笔付款没记上？先看采集日志

「我的 → 采集日志」会记下每一条付款通知收到了什么原文、结果如何：

| 日志标记 | 含义 |
|---|---|
| `记账` | 已经记进账本 |
| `未识别` | 收到了通知，但没解析出金额 / 收支方向，跟着的原文就是判断依据 |
| `跳过` | 本就不该记的（理财收益播报、营销提醒），或解析出来了但被判重丢掉，原因写在日志里 |
| `状态` | 通知使用权连接 / 断开（断开时不会自动记账） |
| `删除` / `导入` | 手动删除、账单导入的执行结果 |

排查顺序一般是：先看有没有 `未识别`（说明通知文案没覆盖到）→ 再看有没有 `状态 断开` → 都没有却还是漏记，就是系统把 App 的通知监听杀掉了，重新进一次「通知使用权设置」即可。

## 三、消费分类：一级类 + 二级类

分类是**两级结构**，记账时先落到二级类，报表再往上汇总到一级类，这样既看得清大方向，也留得住细节。

| 一级类 | 二级类 |
|---|---|
| 饮食 | 餐饮、零食、饮料、水果、聚餐 |
| 出行 | 交通、打车、加油、停车 |
| 日用 | 日用百货、服饰鞋包、家用电器、快递物流 |
| 购物 | 购物、数码电子、美妆护肤 |
| 学校 | 学习用品、培训、书籍 |
| 居住 | 房租房贷、水电燃气、物业、家政 |
| 医疗 | 看病买药、体检、保健 |
| 通讯 | 话费流量、宽带 |
| 爱好 | 娱乐、游戏、运动健身、订阅会员 |
| 其他 | 转账红包、还款、其他 |

收入侧同理：工资报酬、退款、红包转入、其他收入。

- 内置 **200+ 条**关键词规则，开箱即用（例如「星巴克 → 饮食 › 餐饮」「滴滴 → 出行 › 打车」）。
- **识别不出来时不会乱猜**，标记为「待分类」，点进去选一个即可。
- 分类选择页支持搜索、最近使用；底部「添加分类」可以自建二级类（选图标、选颜色、起名字），建完立刻可用，重启也在。
- 在编辑页打开「记住这个商户」开关，以后这个商户会自动归到你选的分类。
- 想批量维护关键词：「我的 → 分类规则」可以新增 / 删除规则。

### 分类能改成你自己的样子

「我的 → 分类管理」把两级分类摊开成一棵可编辑的列表：一级类行下面挂着它的二级类，右边各有一个编辑、一个删除。

| 想做的事 | 怎么做 | 结果 |
|---|---|---|
| 改名 | 点编辑，改名字 | 只改展示名。分类的内部 key 写在历史账目里，永远不会变，老数据照样对得上 |
| 换图标 / 换颜色 | 编辑弹窗里有 53 个线性图标 + 8 个颜色 | 列表、报表、记账页同时生效 |
| 挪一级类 | 编辑弹窗顶部选「归属一级类」 | 这个二级类连带它的报表归属一起搬家 |
| 删除二级类 | 点删除 → 确认 | 它名下的记录**改挂到同级的「其他」**，账不会丢；删之前会告诉你「有 N 笔账目会受影响」 |
| 删除一级类 | 点删除 → 确认 | 组内所有二级类一起降级，报表不再单列这一项（「其他」不能删） |
| 恢复出厂 | 右上角「恢复内置」 | 清掉你对内置分类做过的**改名 / 换色 / 挪位 / 删除**；你自己新建的分类保留 |

自建分类（标签上写「自建」）是真删，连它自己的关键词规则一起清掉；内置分类的 key 不能动，所以改名等操作记成一条「补丁」，因此可以一键还原。

## 四、账单：月度 + 年度

### 月度账单

底部「报表」页会按自然月统计：

- 本月支出总额、收入、笔数、日均支出、**与上月的环比**
- **支出构成环形图** + 按一级类的金额、占比百分比、占比条
- **点一级类进入「分类下钻」页**：概览卡给出它占本月支出的比例与笔数，下面是各二级类的金额排名与占比条，再往下就是这一类的每一笔账；点某个二级类还能继续下钻到「分类明细」页，按天列出
- 收入来源
- 近 6 个月收支趋势柱状图
- 花钱最多的对象 TOP 5
- 本月还有多少笔「待分类」，一键跳去处理

### 年度账单

报表页顶部有一张「年度账单」卡片，点进去是一整年的视角：

- 全年支出、收入、结余、月均支出，以及有账月份、记账笔数、记账天数
- 花得最多的月份、最大单笔
- **12 个月收支走势柱状图**，一眼看出哪几个月花得猛
- **年度分类分布**：环形图 + 一级类排名，点一级类同样进「分类下钻」页，看这一整年的二级类构成与逐笔明细
- 收入来源、花钱最多的对象
- 顶部左右箭头可以翻上一年 / 下一年，跨年对比

## 五、补历史账：导入微信 / 支付宝账单

自动记账只能从装上那天开始。想补齐历史消费：

1. **支付宝**：我的 → 账单 → 右上角「···」→ 开具交易流水证明 / 账单导出，选 CSV，到邮箱下载。
2. **微信**：我 → 服务 → 钱包 → 账单 → 常见问题 → 下载账单 → 用于个人对账，选 CSV。
3. 把 CSV 传到手机，App 里「我的 → 导入微信 / 支付宝账单」，选中文件即可。

支付宝导出的 GBK 编码和微信导出的带 BOM 的 UTF-8 都能正确识别，表头前的说明行会自动跳过，重复记录自动去重。

---

## 六、导出与清理

- **导出账本数据**：生成 UTF-8 BOM 的 CSV，Excel 直接打开不乱码，可自行备份。
- **清空全部数据**：删掉本机所有账目，不可恢复。
- 在明细里点开一条记录 → 右上角的**垃圾桶图标**可以删掉它。删除会留一份「墓碑」，即使通知栏里那条付款通知被系统重新投递一遍，也不会把删掉的记录又写回来。
- 通知抓来的记录，编辑页里把「来源」那一行点开才能看到原始通知全文，平时折起来不占地方。

---

## 七、隐私

- 未申请 `INTERNET` 权限，物理上无法联网。
- 支付通知只提取「金额 / 商户 / 支付方式」等字段，原文留在本机数据库备查，不会外传。
- 无障碍服务只在本地解析支付成功页文本，不开任何辅助操作，默认关闭。
- 卸载应用 = 数据彻底删除。

### 签名配置（密钥不入库）

开发机上 `keystore/ledger-release.jks`（别名 `ledger`）仅用于本地安装验证，正式发布请替换成自己的证书并妥善保管。

### 环境要求（这台机器上已验证可用的组合）

- JDK 17（`D:\develop\Java\jdk-17`，需设置 `JAVA_HOME`）
- Android SDK：`D:\develop\android-sdk`（`platforms;android-35` + `build-tools;35.0.0`），路径写在 `local.properties`
- Gradle 8.10（仓库自带 wrapper，或使用 `~\.gradle\wrapper\dists` 里的缓存发行版）

### 三个容易踩的坑

1. **项目路径含非 ASCII 字符**：AGP 默认会直接拒绝构建，已在 `gradle.properties` 里用
   `android.overridePathCheck=true` 跳过（官方给出的开关）。
2. **`gradle wrapper` 任务**：它会去 `services.gradle.org` 校验发行版 URL，网络不通时会失败。
   本地已缓存该发行版时，用 `--no-validate-url` 即可：
   ```bash
   gradle wrapper --gradle-version 8.10 --distribution-type bin --no-validate-url
   ```
   生成之后 `gradlew` 会直接使用缓存，不再联网。
3. **非 ASCII 路径会让单元测试全军覆没**：路径含中文时，`:app:testDebugUnitTest` 会全部报
   `ClassNotFoundException`（类文件本身没问题，是 Gradle 的 test worker 在中文路径上加载不了）。
   根 `build.gradle.kts` 已把 build 目录重定位到 ASCII 路径 `D:\Project\AutoLedger-build` 绕开它，
   源码路径不用动，**这段逻辑不要删**。

### 3. 界面可视化验收（新增页面逐页截图）

```powershell
powershell -ExecutionPolicy Bypass -File tools\ui-verify.ps1
```

把记一笔、两级分类选择、添加分类、报表下钻、分类明细、年度账单、分类管理、后台常驻挨个点一遍，
每一步截图 + dump UI 树，产物在 `dist/ui-verify/`。断言失败会明确指出是哪一步，并打印当时屏幕上的文案。

> 三个脚本的坑：`.ps1` 必须存成 **UTF-8 带 BOM**（Windows PowerShell 5.1 否则按 GBK 读，
> 中文全乱、引号被撑破）；`uiautomator dump` 只包含**当前屏幕上可见**的节点，
> 所以要断言长页面靠下的模块，必须先滚过去；`uiautomator` 失败时会把设备上**上一屏的 xml**
> 原样留着，dump 前必须先删掉设备侧文件，否则断言会落在旧画面上，报出一堆假失败。

> 为什么要多一个 `paysim` 模块？因为通知的来源包名由系统按**安装包**认定，应用改不了。
> 想让 App 收到一条「来自 `com.tencent.mm`」的通知，就只能真的装一个叫这个名字的包上去。
> 模拟器里没有真微信，这个包名是空的，于是 `paysim` 用两个 flavor 分别伪装成微信和支付宝，
> 只用于测试，不进交付包。
